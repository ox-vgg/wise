# Explore Various Facets of a Dataset
This folder contains various tools to enable exploration of a dataset using different facets (e.g. face).

> **Note:** The features described in this document are still being developed and therefore are not yet stable or ready for production usage.

## Cluster Faces

The `scripts/explore/cluster_faces.py` script uses a semi-supervised, iterative clustering approach to group face embeddings into distinct identities. It is designed to handle very large datasets efficiently while continuously improving based on human feedback.

### Algorithm Overview

The clustering process operates in the following sequential steps:

1.  Data Loading and Filtering: The script begins by loading face embeddings from the pre-computed feature store. It filters out any face vectors that are smaller than a minimum bounding box size (e.g. 32x32 pixels) to reduce noise.

2.  Ground Truth Injection (Iteration 2+): If the user has previously reviewed and confirmed any face clusters using the web interface generated by `scripts/explore/explore.py` script, the algorithm loads these as "known clusters" from the `known_face_clusters` table of `explore.db` SQLite database. This data acts as supervision signal (or ground truth) for the current run. For the first iteration, the `known_face_clusters` table is empty.

3.  Automated Threshold Calibration: If known clusters exist, the script calculates the similarity distances between all faces *within* each known cluster. It uses the 90th percentile of these internal distances to automatically calculate an optimal density threshold (`eps`) for the dataset. If no known clusters exist (Iteration 1), it uses the fallback threshold provided by the user.

4.  Sparse Graph Construction: The script builds a K-Nearest Neighbors (KNN) graph of all valid faces using the FAISS library. This creates a highly efficient sparse distance matrix, connecting each face only to its most similar neighbors, bypassing the memory limits of dense pairwise calculations.

5.  Applying Constraints (Must-Link and Cannot-Link): The sparse matrix is manipulated using the ground truth data to guide the clustering algorithm:
    *   **Must-Link:** The distance between any two faces that belong to the same known cluster is forced to a near-zero value, ensuring they will be grouped together.
    *   **Cannot-Link:** The distance between any two faces that belong to different known clusters is forced to maximum, severing the connection and guaranteeing they will never be merged.

6.  Density-Based Clustering (DBSCAN): The [DBSCAN](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.DBSCAN.html) algorithm is applied to the constrained sparse matrix using the calibrated threshold. Because of the forced constraints, the algorithm naturally flows through the unreviewed data while strictly respecting the boundaries of the known identities.

7.  Assignment and Resolution: The resulting DBSCAN groups are analyzed. If a group contains faces from a known cluster, all unreviewed faces in that group are "absorbed" and assigned to that known identity. Any group without known faces becomes a new "draft" cluster for future review.

### The Iterative Workflow

The system is designed to be used iteratively:

*   Iteration 1: Run the script with a strict similarity threshold. The algorithm groups the most obvious matches into many small, high-purity draft clusters.

```bash
python3 scripts/explore/cluster_faces.py \
  --project-dir /data/wise-projects/wise-test-dataset/\
  --feature-extractor-id "deepinsight/insightface/buffalo_l/_unknown"\
  --k-neighbors 50 \
  --similarity-threshold 0.7
```

*   Review Phase: Use the web interface to merge these small draft clusters belonging to the same person and mark them as "Reviewed". The web interface is made available at `http://localhost:10101/wise-test-dataset/explore/` using the command show below.

```bash
python3 scripts/explore/explore.py \
   --project-dir /data/wise-projects/wise-test-dataset/ \
   --port 10101
```

*   Subsequent Iterations: Run the `scripts/explore/cluster_faces.py` script again. It now uses the manually reviewed clusters to calibrate the threshold and constrain the graph. It will automatically absorb thousands of unreviewed faces into the known clusters and intelligently restructure the remaining draft clusters based on the newly learned density of the dataset. This cycle repeats, requiring less manual effort in each iteration.

## Identify Faces

The `scripts/explore/identify_faces.py` script cross-references an unreviewed dataset against a known knowledge base to automatically propose identities for unreviewed clusters, turning manual data entry into a fast verification workflow. To use this feature, you need two distinct WISE projects:

1. The UNKNOWN Project: The primary project containing your unlabelled media (e.g., video footage). This project must have been processed by `cluster_faces.py` so that an `explore.db` database exists containing `draft` clusters.
2. The KNOWN Project: A secondary WISE project built specifically to act as a knowledge base. This project typically contains hundreds or thousands of single-face profile images with known identities. The identities for each profile image is stored in a metadata table named `metadata-profiles` in its `internal.db`, populated with metadata fields like `name`, `reference_url` linked to the vectors. The KNOWN project can be created by: (a) collecting a set of profile images of known individuals and their metadata in a CSV file, (b) creating a WISE image project based on these images, and finally (c) using the `media-metadata.py` script to import the known identities for each profile image as a media level metadata in WISE.

For each face cluster, the script finds a profile match in the KNOWN project based on the similarity threshold and marks them as proposals. If `--similarity-threshold` is not provided, the script automatically infers an optimal threshold using natural variance of face similarity in the verified clusters. Human annotators can review these proposals using the user interface generated by `scripts/explore/explore.py` and selecting `Identity Proposed` entry in the machine feedback dropdown.

Here is an example workflow:

1.  Run the identification script, providing paths to both projects:

```bash
python3 scripts/explore/identify_faces.py \
   --unknown-project-dir /data/wise-projects/unknown/ \
   --known-project-dir /data/wise-projects/manually_annotated_profiles/ \
   --feature-extractor-id "deepinsight/insightface/buffalo_l/_unknown" \
   --metadata-table "metadata-profiles" \
   --name-field "name" \
   --similarity-threshold 0.6 \
   --status-filter reviewed
```

2.  Open the Explore Web UI (`explore.py`).
3.  Use the Machine Feedback dropdown to filter for `Identity Proposed`.
4.  Click into a proposed cluster. A prominent banner will display the proposed Wikipedia identity, confidence score, and a link to the profile.
5.  If the cluster's faces match the proposal, click Accept to:
    * update the `cluster_label` to the person's real name,
    * permanently save other profile metadata into the cluster's metadata, and
    * mark the cluster as `Reviewed`.
